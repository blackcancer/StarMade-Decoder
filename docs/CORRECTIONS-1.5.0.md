# Data-integrity corrections — 1.5.0

## Scope and reference

This change set starts at StarMade-Decoder `e5f5314`. The inspected Java reference
is the accessible `blackcancer/StarMade-Open` fork at `decf3a1`, not a claim about
a later Schine revision. It corrects the audited binary primitives, SMD3 writers,
archive traversal, packaging and silent-recovery behavior.

## Compatibility contract

`readJavaUTF` and `writeJavaUTF` now mean **Java Modified UTF-8** for both saved
Tags and network payloads. ASCII and ordinary BMP text remain compatible. NUL,
supplementary characters and lone UTF-16 surrogates now match Java. Invalid
continuations are rejected without advancing the reader.

SMD3 version 6 uses zlib-compressed little-endian 24-bit words. Version 7 uses
**raw LZ4 blocks** and 32-bit native-memory words (little-endian on the supported
x86/x64 game installations), not zlib. The parser also handles the pinned Java
revision's `22` compressed-header field variant by respecting the enclosing
sector's declared boundary. Files incorrectly generated by older SDK versions
with zlib-labelled-v7 payloads are rejected rather than guessed.

SMD3 writing preserves decoded fields, including all six reserved bits; it does
not promise identical compression, padding, allocation or file bytes. Version 7
is the default output. Version 6 must be explicitly requested and rejects types
or extra bits that it cannot represent. Versions older than 6 and SMD/SMD2
resources require a separate migration layer and are explicitly unsupported.

The current header/sector layout cannot contain every incompressible segment.
An oversized compressed segment produces an error before any output is returned;
it is never truncated. No multi-sector storage extension has been invented.

`SINGLE_SIDE_EDGE` needs the game's three clipping normals. Supply
`icoSideNormals: readIcoSideNormals(icoVectorsBytes)` using `data/IcoVectors.bin`
from the relevant installation. Missing geometry is an error, not a solid cube.

## Strict parsing and recovery

`parseSmd3`, `parseSment` and `parseBlueprintFolder` default to strict behavior.
Malformed mandatory headers, embedded Tags, segment payloads and logic maps are
no longer silently discarded. Optional absent metadata files remain optional.
Recovery must be requested with `{ mode: 'recover' }`; check `complete` and the
`diagnostics` array before using partial results. `writeSmd3` rejects recovered,
incomplete files. Resource exhaustion remains fatal even in blueprint recovery.

Defaults are configurable per call: 4096 decoded segments, 20000 archive entries,
4096 entities, attachment depth 64, 64 MiB per entry, 512 MiB total declared file
bytes and 256 MiB compressed archive bytes. Segment storage stays compact until
its mutable `blocks` array is first accessed. Accessing every block of a very
large blueprint still requires proportionate memory.

Tag defaults are 64 MiB input, 128 MiB decompressed data, depth 128, one million
Tags and 64 MiB per byte array. Standalone callers can enable
`rejectTrailingBytes`; Java-compatible envelope parsing allows trailing bytes by
default. Writers reject cyclic trees, heterogeneous lists and missing or
misplaced STRUCT terminators. Unknown factory formats are not guessed.

Folder reads reject symbolic links. ZIP paths and duplicate entries are checked.
Attachment ancestry is based on exact prefixes; there is no silent depth-five
cutoff and no cross-sibling phantom-child construction.

## Editing

```ts
const segment = emptySegment();
setBlock(segment, 1, 2, 3, {
  type: 5, hp: 100, active: false, orientation: 0, extra: 0,
});
const output = writeSmd3({ ...emptySmd3File(), segments: [segment] });
```

Blocks created by empty/SINGLE decoding are independent. Writers validate actual
blocks and never rely on the caller's cached `blockCount`. Direct array edits
remain supported; `setBlock` copies its input and refreshes cached occupancy.

## Validation and known limits

Local Node 22.16 validation before this checkpoint:

- TypeScript build and declaration JSDoc checks passed.
- 662 tests passed; 59 tests were explicitly pending because required external
  installation fixtures were unavailable. They are not counted as passes.
- Coverage gate passed: 88.82% statements/lines, 78.71% branches and 76.88%
  functions in the measured source. These values are not format coverage.
- A real JDK independently verified nine UTF vectors in both directions and
  five malformed sequences, including the 65535-byte limit.
- Thirty-two generated raw LZ4 blocks were independently decoded by native
  liblz4 during development. A liblz4-generated fixture is committed as a
  decoder regression, separate from SDK-to-SDK round trips.
- The complete 43-file committed metadata corpus is now actually traversed by
  its writer test; the former directory scan exercised zero files.

The production-only packed-consumer test requires npm registry access and runs
in CI. CI uses the committed dependency lock without rewriting it during tests.
Set `STARMADE_DIR` to supply installed-game configuration assets for the dedicated
live tests. Historical tests with other hard-coded installation paths still
report themselves pending when their specific fixtures are absent.

No complete game runtime was launched for this qualification. Real v7 game
fixtures and in-game re-import validation remain necessary before claiming full
StarMade-version compatibility. The SDK's unrelated high-level game schemas
have not all been independently requalified by this correction set.
